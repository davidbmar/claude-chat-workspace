## Goal

Add server-side endpoints to retrieve and manage conversation history by ID, as specified in sprint 3 AGENT_BRIEF.md.

## Context

The conversations Map already existed in server.js to store per-session history. Sprint 3 requires exposing this data via REST endpoints so the frontend (future history sidebar) can enumerate and retrieve sessions.

## Plan

Add three endpoints to server.js:
1. GET /api/conversations — list all active conversation IDs
2. GET /api/conversations/:id — return message history for a given ID
3. DELETE /api/conversations/:id — remove a conversation from the Map

## Changes Made

- `server.js`: Added GET /api/conversations, GET /api/conversations/:id, and DELETE /api/conversations/:id endpoints between the health check and chat endpoints.

## Decisions Made

- Endpoints are scoped to the in-memory Map only; no persistence layer was introduced (in-memory state resets on restart, consistent with existing design).
- Return 404 with `{ error: 'not found' }` for unknown IDs on both GET and DELETE.
