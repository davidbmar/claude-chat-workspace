## Goal

Fix B-001 (model selector ignored by server) and B-002 (system prompt uses fake user message instead of Anthropic system parameter).

## Context

Sprint 2. The frontend sends a `model` field in the request body, but server.js was ignoring it and always reading from env var. System prompt was injected as a fake user message rather than using the Anthropic `system` top-level field.

## Plan

1. Extract `model` from req.body in /api/chat
2. Pass model to streamResponse() as a parameter
3. streamResponse() uses the passed model with fallback to env var
4. Remove fake user message system prompt injection
5. Add `system` field to messages.stream() options when SYSTEM_PROMPT is set

## Changes Made

- `server.js`: streamResponse() now accepts `model` parameter, uses it with fallback to env var
- `server.js`: /api/chat extracts `model` from req.body alongside message and conversationId
- `server.js`: removed fake user message system prompt injection
- `server.js`: system prompt now passed as `system:` top-level field in messages.stream() options

## Decisions Made

- System prompt is added to streamOptions only when non-empty (truthy check on process.env.SYSTEM_PROMPT) — consistent with B-002 requirement
- Model fallback chain: request body → CLAUDE_MODEL env var → 'claude-sonnet-4-6'
